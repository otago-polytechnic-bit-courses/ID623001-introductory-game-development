Learning to use AI tool is an important skill. While AI tools are powerful, you \textbf{must} be aware of the following:

\begin{itemize}
    \item If you provide an AI tool with a prompt that is not refined enough, it may generate a not-so-useful response
    \item Do not trust the AI tool's responses blindly. You \textbf{must} still use your judgement and may need to do additional research to determine if the response is correct

\end{itemize}

\subsection*{Functionality - Learning Outcome 1 (55\%)}
\textbf{Pong - 10\% (Individual)}
\begin{itemize}
    \item Build and publish the game to \textbf{itch.io}.
	\item Implement the fundamental mechanics of the game, including:
	\begin{itemize}
        \item Main menu - The game should have a main menu with options to start the game, view the high scores and exit the game.
        \item Paddle movement - The player should be able to move the paddle up and down using the \textbf{W} and \textbf{S} keys using the \textbf{Unity} input system.
        \item Ball movement.
        \item Collisions - The ball should bounce off the top and bottom walls and the paddles.
        \item Score system - One point should be awarded to the player who scores a goal.
        \item Score display - The scores of both players should be displayed on the screen.
        \item High scores - The game should store and display the top \textbf{10} high scores.
        \item Pause and resume - The player should be able to pause and resume the game using the \textbf{P} key.
        \item Sound effects - The game should have sound effects for the ball bouncing off the walls and paddles, scoring a goal and the game ending.
        \item Game over - The game should end when a player reaches a score of \textbf{10}.
        \item End game menu - The game should have an end game menu with options to play again, view the high scores and exit the game.
    \end{itemize}
    \item Tier 2 mechanics. Select \textbf{three} mechanics from the list below:
    \begin{itemize}
        \item AI paddle - An AI paddle that moves up and down.
        \item Difficulty levels - Easy, medium and hard difficulty levels that adjust the speed of the AI paddle.
        \item Ball speed - The speed of the ball should increase after a certain number of goals.
        \item Countdown timer - A countdown timer that starts the game after a certain number of seconds.
        \item Customisation - Asset options for the paddles and ball.
        \item Music - Background music that plays during the game.
    \end{itemize}
    \item Tier 3 mechanics. Select \textbf{two} mechanics from the list below:
    \begin{itemize}
        \item Multiple rounds - Best 3 out of 5 rounds to win the game.
        \item Power-ups - Random drops that allow the player to increase the size of the paddle and slow down the ball.
        \item Trail effects - Trail effects for the ball.
        \item Sound settings - Options to adjust the volume of the sound effects and music.
    \end{itemize}
    \item Three mechanics of your choice. These mechanics should be different from the ones listed above. 
\end{itemize}

\subsection*{Code Quality and Best Practices - Learning Outcome 1 (40\%)}
\begin{itemize}
    \item Project Structure - The codebase should be well-organised with a clear and logical structure that separates concerns and promotes reusability and maintainability.
	\item Naming Conventions - File, class, method, variable, constant and property names should be clear, descriptive and consistent across the codebase. 
    \item Documentation and Comments - The codebase should be well-documented using the \textbf{XML} documentation format with comments that explain complex logic and clarify the purpose of classes, methods or complex sections. 
    \item Code Formatting - Consistent indentation and spacing should be used across the codebase. It includes ensuring proper indentation for code blocks, following a standard format for braces and adding blank lines between sections. 
    \item Dead Code - The codebase should not contain unused or redundant files, classes, methods, variables, constants or properties. Keeping unnecessary codebase around can lead to confusion, clutter and potential bugs down the line.
    \item Performance and Scalability - The codebase should be optimised for performance, using efficient algorithms and data structures to minimise bottlenecks. 
\end{itemize}
